A reflexive research project

When the framework studies itself.

DIO to DIO examines how different large language models reconstruct and explore Digital Identity Optimization (DIO) and the Ontology of Digital Identity (ODI) when the framework is applied to its own distributed ecosystem.

Nine independent model analysesDIO/ODI-native explorationGraph-theoretical perspectivesMarkdown · PDF · HTML representations

01 / Project

One research object. Independent analytical outputs.

The project is reflexive: DIO/ODI is both the subject of inquiry and the conceptual perspective through which that subject is examined. The research concerns how large language models reconstruct the framework when it is applied to its own distributed ecosystem, and how each model develops its own interpretation and graph-theoretical account.

The shared research assignment establishes the object of inquiry and broad analytical directions. It does not prescribe one graph schema, one set of node and edge types, one observation boundary, or one conclusion. Each report retains the concepts, methodological choices, analytical emphasis, graph model, and interpretation developed in that report.

02 / Research question

How do models reconstruct DIO from within DIO?

How do large language models reconstruct and examine Digital Identity Optimization (DIO) when the framework is applied to itself, and what do their independently developed interpretations and graph-theoretical analyses reveal about the DIO/ODI ecosystem?

03 / Research design

A shared assignment, not a shared interpretation.

Common research object

All reports investigate the distributed DIO/ODI ecosystem through a reflexive application of the framework's own conceptual resources.

Open-ended analytical development

Models were able to develop their own questions, analytical emphases, evidential routes, and interpretive findings within the common assignment and its methodological constraints.

Report-specific graph models

Graph boundaries, node classes, edge semantics, entry points, and measurements are documented as each report defines them. Their numerical outputs are not treated as directly comparable scores.

Documented prompt arrangements

Eight reports include staged research and revision prompt components in their appendices. Leo AI documents one author-designed integrated prompt. The original appendices remain inside the reports.

04 / Research archive

Nine reports. Nine independent readings.

Each catalogue description identifies the scope and approach of its own report. It is not a summary that replaces the report, nor an attempt to harmonize the different interpretations.

The report catalogue is generated from the factual metadata in metadata/analyses.json.

05 / Publication principles

Faithful representation, not editorial harmonization.

01

Markdown source

Each original Markdown file is preserved unchanged and directly accessible in the browser. It is also the authoritative text source for the generated HTML representation.

02

PDF source

Each original PDF is preserved unchanged and linked for direct browser viewing.

03

Faithful HTML

Each HTML report body is generated from its corresponding original Markdown file. Prose, order, headings, tables, references, code blocks, and appendices are retained.

04

Factual catalogue

Descriptions and report metadata are a separate identification layer. They do not replace or edit the source text.

05

No common synthesis

This portfolio does not rank, merge, or harmonize the reports. Any future meta-analysis would require its own research question, method, and standalone publication.
